# extract_slides

Извлечение скриншотов слайдов из видео с лекциями, презентациями и вебинарами.

Скрипт анализирует видео, находит моменты смены слайдов, ждёт заданную задержку
(по умолчанию 1 секунду) и сохраняет кадр в PNG. На каждом скриншоте снизу
добавляется белая полоса с временно́й меткой формата `HH:MM:SS`, а имя файла
содержит ту же метку в формате `HH-MM-SS`.

---

## Возможности

- 🔍 **Автоматический поиск смены слайдов** через OpenCV (попиксельное сравнение).
- ⏱ **Точная привязка ко времени**: сравнение сэмплов раз в N секунд (по умолчанию 1.0).
- ⏸ **Задержка после смены слайда** (по умолчанию 1 секунда) — чтобы не поймать
  переходный эффект и начало рисования поверх слайда.
- 🖼 **Подпись на скриншоте**: снизу добавляется белая полоса с меткой `HH:MM:SS`.
- 📁 **Имя файла с меткой**: `slide_HH00-MM03-SS29.png`.
- 🧪 **Режим проверки порога** (`--check-only`) со статистикой и рекомендациями.
- ⚙️ **Все параметры настраиваются из командной строки**.

## Использование

### 1. Проверка порога (без сохранения кадров)

Полезно запустить первым делом, чтобы понять, какие значения `changed_ratio`
и `pixel_diff` подходят для вашего видео.

```bash
python3 extract_slides.py 05.mp4 --check-only
```

Скрипт выведет:
- статистику различий между соседними сэмплами (min / max / mean / median / перцентили);
- гистограмму распределения;
- конкретную рекомендацию по `--changed-ratio`.

### 2. Извлечение слайдов

```bash
python3 extract_slides.py 05.mp4 slides \
    --changed-ratio 0.03 \
    --pixel-diff 30
```

Результат — PNG-файлы в папке `slides/`:

```
slides/slide_HH00-MM03-SS29.png
slides/slide_HH00-MM03-SS55.png
slides/slide_HH00-MM04-SS31.png
...
```

Каждый файл выглядит так:

```
┌───────────────────────────────────────┐
│                                       │
│           слайд (как был)             │
│                                       │
├───────────────────────────────────────┤
│        HH:00 MM:03 SS:29              │  ← белая полоса 50 px
└───────────────────────────────────────┘
```

## Параметры командной строки

| Параметр | По умолчанию | Описание |
|---|---|---|
| `video` | — | Путь к видеофайлу (обязательный) |
| `output_dir` | `slides` | Папка для сохранения скриншотов |
| `--check-only` | выкл | Только анализ порога, без сохранения кадров |
| `--pixel-diff` | `30` | Порог разницы яркости одного пикселя (0–255) |
| `--changed-ratio` | `0.05` | Доля изменившихся пикселей (0.0–1.0) |
| `--sample-interval` | `1.0` | Интервал между сэмплами, сек |
| `--min-gap` | `2.0` | Минимум секунд между сменами слайдов |
| `--capture-delay` | `1.0` | Задержка после смены слайда, сек |
| `--label-height` | `50` | Высота белой полосы под слайдом, px |

## Примеры

```bash
# Только проверка порога
python3 extract_slides.py 05.mp4 --check-only

# Проверка с более агрессивной фильтрацией шума
python3 extract_slides.py 05.mp4 --check-only --pixel-diff 50

# Извлечение с настройками по умолчанию
python3 extract_slides.py 05.mp4

# Извлечение с явными порогами и высокой полосой
python3 extract_slides.py 05.mp4 slides \
    --changed-ratio 0.03 --pixel-diff 30 --label-height 80

# Более частое сэмплирование (точнее поймает момент смены)
python3 extract_slides.py 05.mp4 slides --sample-interval 0.5

# Увеличить задержку, чтобы избежать попадания рисунков автора
python3 extract_slides.py 05.mp4 slides --capture-delay 2.0

# Справка
python3 extract_slides.py --help
```

## Как подобрать пороги

1. Запустите `--check-only`:

   ```bash
   python3 extract_slides.py 05.mp4 --check-only
   ```

2. Посмотрите на гистограмму. Идеальная картина:
   - основная масса значений — в первых двух бакетах (шум);
   - несколько значений — в последних (смены слайдов).

3. Скрипт сам предложит `--changed-ratio`. Скопируйте его в команду извлечения.

4. Если рекомендация не помогла:
   - **много ложных срабатываний** → увеличьте `--pixel-diff` до `50`
     или `--changed-ratio` до `0.08–0.10`;
   - **пропускает смены слайдов** → уменьшите `--changed-ratio` до `0.02–0.03`
     или `--sample-interval` до `0.5`.

## Как это работает

1. **Сэмплирование.** Скрипт последовательно читает видео и берёт каждый N-й кадр,
   где N = `fps * sample_interval`. Это быстро, потому что используется `cap.grab()`
   без декодирования пропускаемых кадров.

2. **Сравнение.** Каждый сэмпл уменьшается до 640×360 и переводится в оттенки серого.
   Текущий сэмпл сравнивается с последним **подтверждённым** слайдом.
   Считается доля пикселей, где разница яркости превышает `pixel_diff`.

3. **Фиксация смены.** Если доля превышает `changed_ratio` и с прошлой смены
   прошло больше `min_gap` секунд — смена фиксируется, «стабильный» кадр обновляется.

4. **Извлечение.** Для каждой найденной смены берётся кадр на `capture_delay` секунд
   позже. Снизу добавляется белая полоса с меткой `HH:MM:SS`, и файл сохраняется
   под именем `slide_HHxx-MMxx-SSxx.png`.

## Формат имён файлов

| Часть | Значение |
|---|---|
| `slide_` | префикс |
| `HH00` | часы в видео |
| `MM03` | минуты |
| `SS29` | секунды |
| `.png` | формат (PNG без потерь) |

Пример: `slide_HH00-MM03-SS29.png` — слайд, снятый на 00:03:29.

## Известные ограничения

- Если видео закодировано с ключевым кадром на каждом кадре (например, lossless-запись
  экрана), фильтр `scene` в FFmpeg может не работать. Этот скрипт использует OpenCV,
  поэтому таких ограничений не имеет.
- При очень плавных переходах (длительное затухание) первый зафиксированный сэмпл
  может попасть на середину перехода. Решение — уменьшить `--sample-interval`
  или увеличить `--capture-delay`.
- Скрипт не распознаёт рисунки автора поверх слайда как отдельные события —
  они игнорируются, потому что сравнение идёт с «подтверждённым» кадром.
